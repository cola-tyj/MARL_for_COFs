v2 不是对 v1 的替换或重新编码。它从同一份 `final_dataset.csv` 和 XYZ 直接重建
canonical layer，再通过 molecule/package index 增加独立 annotation。任何模型都应把
`cof_graphs.npz` 中的 atomic number、formal charge、bond graph 和 XYZ 视为 ground truth。

当前 2,532 条 RDKit canonical isomeric SMILES 全部唯一，因此 manifest 明确记录
`one_conformer_per_smiles=true`。构建过程没有因为 SMILES 或构象相似而删除记录。

## 二、v1：canonical molecular dataset

### 2.1 输入和严格检查

每条记录以 CSV 行号为固定 package index：

1. 使用 RDKit 解析 SMILES 并添加显式 H；
2. 读取对应 XYZ；
3. 严格比较 SMILES 与 XYZ 的原子数、元素组成和原子顺序；
4. 禁止缺失路径、NaN/Inf、未知元素和元素 fallback；
5. 从 SMILES/RDKit 获取真实化学键，不按距离猜测键级；
6. 坐标逐分子减去算术质心，原始 centroid 单独保存。

固定元素词表为：

```text
H, C, N, O, F, B, P, S, Cl, Br, I, Si, Sn
```

### 2.2 紧凑存储

`cof_graphs.npz` 将所有分子的数组展平，并使用 `atom_offsets`、`bond_offsets` 定位单个
分子。主要数组包括：

- `atom_types`、`atomic_numbers`、`formal_charges`、`radical_electrons`；
- `positions`、`centroids`；
- `bond_index`、`bond_types`；
- `atom_offsets`、`bond_offsets`。

无向化学键只保存一次，键型为 `none/single/double/triple/aromatic`；其中 `none=0`
只用于模型的 full-pair 表示，不写入 sparse edge list。

### 2.3 固定划分

| 划分 | train | val | test | 约束 |
|---|---:|---:|---:|---|
| IID | 2,026 | 253 | 253 | 按 `Target_PG` 分层 |
| Core-OOD | 2,024 | 250 | 258 | Core 在集合间完全隔离 |

D6h 只有两个 Core，Core-OOD 中分别进入 train 和 test，val 不含 D6h。D6h 结果必须标记
为 low-support/exploratory，不能作为主要 quantitative conclusion。

### 2.4 v1 文件

- `cof_graphs.npz`：canonical 数组；
- `metadata.csv`：分子信息、相对 XYZ 路径和 split 标签；
- `vocab.json`：原子/键词表；
- `statistics.json`：元素、键、电荷和规模统计；
- `split_iid.json`、`split_core_ood.json`：固定划分；
- `manifest.json`：源 CSV、全部 XYZ、数据文件 SHA-256 和数据指纹。

## 三、v2：symmetry annotation 与模型适配层

### 3.1 点群标签

v2 明确区分：

- `target_pg`：分子构建目标；
- `analyzer_pg`：pymatgen 直接重算的候选 Schoenflies 标签；
- `actual_pg`：候选操作经过标准有限群重建、同元素 Hungarian assignment、RMS tolerance、
  群闭包和 permutation 群乘法验证后得到的最大完整点群；
- `pg_exact_match`：`target_pg == actual_pg`；
- `pg_compatible`：target operation group 是 actual operation group 的子群。

统一协议：

| 参数 | 值 |
|---|---|
| analyzer | `pymatgen.symmetry.analyzer.PointGroupAnalyzer` |
| symmetry tolerance | 0.3 Å |
| eigen tolerance | 0.01 |
| matrix tolerance | 0.1 |
| assignment | 按元素分块的 `scipy.optimize.linear_sum_assignment` |
| operation acceptance | operation RMS assigned distance ≤ 0.3 Å |

pymatgen 的候选标签和返回生成元不总能直接形成完整有限群。例如，部分近似结构会被标为
D2，但只有一个非平凡 C2 操作；v2 保留原始 `analyzer_pg`，同时把 `actual_pg` 严格降为
经过完整验证的 C2，而不是补造或静默接受缺失操作。

### 3.2 操作、置换与轨道

对 actual 和 target group 分别保存：

- 完整 `R_g ∈ O(3)` 操作矩阵；
- 同元素约束的 `permutation_index[g, i] = j`；
- operation-level RMS/max symmetry error；
- 分子级 mean/max error；
- `orbit_id` 和 `orbit_size`。

约定为：

```text
positions @ R_g.T ≈ positions[permutation_index[g]]
```

不保存 `N×N` permutation matrix。验证器会检查矩阵正交性、群阶、群闭包、元素保持双射、
矩阵误差重算，以及 permutation 对群乘法的同态一致性。

### 3.3 RDKit 衍生特征

`rdkit_features.npz` 保存 hybridization、aromaticity、chirality、degree、显式 H 邻居数、
ring membership、bond stereo、conjugation 和 bond ring membership。这些字段是可复现的
模型输入特征，不覆盖 canonical ground truth。

### 3.4 模型 adapter

- EQGAT：`SparseGraphAdapter` 继续返回 canonical sparse graph；
- MiDi：`MiDiAdapter` 加载时动态构造 `[N,N]` full-pair bond types；
- UAE-3D：`UAE3DAdapter` 动态构造 full-pair bonds，并执行官方词表映射；
- canonical 数据始终保留显式 H，adapter 可选择 `include_h=False`，同时重编号边、轨道和
  symmetry permutation。

UAE-3D 官方 GEOM 词表不包含 Sn。当前数据有 2 个含 Sn 分子、共 4 个 Sn 原子，v2 提供：

1. `compatible_subset`：2,530 个分子，排除两条 Sn 记录；
2. `extended_vocabulary`：在官方 16 类词表后增加 `Sn=16`。

Sn 不允许映射为 C 或 Si。

### 3.5 v2 验证结果

| 指标 | 结果 |
|---|---:|
| pymatgen 重算标签与历史标签一致 | 2,513/2,532（99.25%） |
| validated actual 与历史标签一致 | 2,219/2,532（87.64%） |
| target 与 actual 完全相同 | 1,456/2,532（57.50%） |
| target 是 actual 的子群 | 2,532/2,532（100%） |
| actual operation RMS mean / P95 / max | 0.00965 / 0.0681 / 0.2193 Å |

`validated actual` 一致率低于 pymatgen 标签一致率不是原子/坐标错误，而是完整群操作验证
主动降级了不完整的候选高对称标签。

### 3.6 Core-OOD 相似度审计

Morgan fingerprint 使用 radius=2、2,048 bits、chirality=true、无显式 H。Core-OOD test
到 train 的最大 Tanimoto：

- mean=0.676；
- median=0.653；
- 258 条中 57 条为 1.0，68 条不低于 0.8。

因此 Core-OOD 只保证 Core 标签隔离，不等价于严格的低结构相似度 OOD。后续报告必须
同时给出连续 Tanimoto 分布；若研究结论需要强结构 OOD，应新增 fingerprint-threshold
split，而不是修改或覆盖现有 Core-OOD split。

## 四、复现与验证

```bash
# v1
python -m generative_model.data.build_cof_package
python -m generative_model.data.build_cof_package --verify-only

# v2
python -m generative_model.data.build_v2_package --workers 12
python -m generative_model.data.validate_v2 \
  --package generative_model/data/processed/v2

# 全部测试
python -m unittest discover -s generative_model/tests -v
```

数据包测试与连续两次完整构建均已通过，15 个 v2 输出文件字节一致。manifest 记录
Python、RDKit、NumPy、SciPy、pymatgen 版本、builder Git commit 与源码 SHA-256、schema、
元素词表、坐标单位/dtype、split seed、symmetry protocol 和全部数据文件 hashes。
