# 项目静态上下文

**版本**：1.0  
**用途**：后续任务默认复用的精简背景和固定约束；不记录 checkpoint、最新 loss、临时状态
或阶段性实验数字。当前进度见 [项目动态状态](项目动态状态.md)。

## 1. 项目目标与边界

- 目标是生成可作为 COF 构筑单元的 3D 分子，并最终支持指定点群条件和后续 MARL 优化。
- 数据、模型适配、生成模型、统一评测、点群条件和 MARL 必须分层；下游实验不得反向修改
  canonical ground truth。
- `symmetry-conditioned diffusion` 属于历史失败路线，不是当前实现基础，除非用户明确重启。
- 先证明无条件重构/生成质量，再加入 point-group condition；不能用条件命中掩盖基础化学
  有效性问题。

## 2. 冻结数据契约

- 唯一源索引是 `cof_symmetry_pipeline/output/final_dataset.csv`；当前冻结版本为 2,532 条，
  一条记录对应一个构象，`one_conformer_per_smiles=true`。
- canonical 数据位于 `generative_model/data/processed/v2/cof_graphs.npz`，v1/v2 的 canonical
  分子数组字节一致；v2 只增加独立 annotation/feature 层。
- canonical ground truth 是 atomic number、atom type、formal charge、radical electrons、
  RDKit/SMILES 化学键和 XYZ。坐标单位为 Å，逐分子质心归零，原 centroid 单独保存。
- 固定 13 元素词表为 `H/C/N/O/F/B/P/S/Cl/Br/I/Si/Sn`，保留显式 H。Si、Sn 必须独立
  表示；未知元素、Sn、charge 或 radical 不允许映射到 C/Si 或静默置零。
- 无向化学键在 canonical 层只保存一次，采用 sparse `bond_index`/`bond_types` 和
  `atom_offsets`/`bond_offsets`；`none=0` 只由需要的 adapter 在加载阶段构造。
- 不因 SMILES 相同或结构相似而默认删除不同 3D conformer。若数据定义改变，必须显式更新
  manifest，而不能在 adapter 或训练脚本中隐式去重。

## 3. Symmetry 语义

- `target_pg` 是构建目标，`analyzer_pg` 是 pymatgen 候选标签，`actual_pg` 是完整操作、同元素
  Hungarian assignment、容差、闭包和 permutation 群验证后的实际标签。
- `pg_exact_match` 表示 target 与 actual 相同；`pg_compatible` 表示 target operation group
  是 actual operation group 的子群。
- 固定分析协议为 `PointGroupAnalyzer`：symmetry tolerance `0.3 Å`、eigen tolerance
  `0.01`、matrix tolerance `0.1`；assignment 按元素分块。
- 操作保存为 `R_g ∈ O(3)`，置换保存为长度 N 的 index，约定
  `positions @ R_g.T ≈ positions[permutation_index[g]]`；禁止保存 N×N permutation matrix。
- symmetry、orbit 和 RDKit 衍生特征是独立 annotation，不覆盖 canonical ground truth。
- D6h 支持量很小，固定标记为 low-support/exploratory，不用于主要定量结论。

## 4. 模型无关架构

```text
final_dataset.csv + XYZ
        ↓ strict builder/validator
canonical sparse molecular dataset
        ├── symmetry/operation/orbit annotations
        ├── reproducible RDKit features
        └── model adapters
              ├── sparse graph（如 EQGAT）
              └── runtime full-pair none/bond representation（如 UAE/MiDi）
        ↓
reconstruction / generation model
        ↓
统一 chemistry + 2D + 3D + symmetry evaluator
        ↓
PG condition / symmetry method / MARL（通过前置 Gate 后）
```

- canonical 层始终模型无关。模型特有 vocab、是否移除 H、full-pair tensor、padding 和条件
  embedding 只存在于 adapter/loader/model 层。
- UAE 类路线必须把 autoencoder 重构与 latent generation 分开验收；重构通过不等于生成通过。
- Core-OOD 只保证 Core 标签隔离，不等价于低 fingerprint similarity；结论必须同时报告
  test-to-train 最近邻 Morgan/Tanimoto。

## 5. 编码与数据安全规范

- 严格失败：缺字段、未知类别、NaN/Inf、索引越界、原子/键/XYZ 不一致或 hash/schema
  不匹配时立即报错，不做 fallback、猜测修复或静默丢弃。
- 上游官方模型源码保存在 `generative_model/external/`，按锁定 commit 使用并保持 clean；项目
  适配代码写在本仓库模块中，不直接修改 upstream checkout。
- 保持模块化：builder、dataset、adapter、objective、trainer、evaluator 和报告生成分离；
  不把模型专用字段写回 canonical NPZ。
- 所有 split、vocab、随机种子、容差、版本、Git commit、数据指纹和 SHA-256 都应进入
  manifest、checkpoint identity 或报告。
- 可重复构建的数据包要求相同输入和环境下字节一致；训练至少要求固定 seed、固定评估输入、
  完整 RNG/optimizer checkpoint 和参数级恢复一致性审计。
- 仓库可能有用户未提交修改。只编辑任务相关文件，保留无关变更；不得用 destructive Git
  命令清理工作树。

## 6. 测试与实验规则

- 修改 Python 后至少执行 `py_compile` 和直接相关单元测试；修改数据接口还要执行严格失败、
  canonical↔adapter round-trip、shape/index/元素和 hash/fingerprint 检查。
- 修改训练器后先做 1–2 step 工程 smoke，检查 forward/backward、有限 loss/gradient、保存、
  严格恢复和固定输入评估；工程通过不等价于模型质量通过。
- 模型质量按冻结的 `1 → 4 → 32 → full train` Gate 逐级放行。失败时停止扩大数据或训练，
  保存报告并先诊断。
- 评估必须覆盖数值稳定性、RDKit sanitize、连通性、原子/键、坐标/几何、碰撞、唯一性、
  novelty、最近邻相似度和 actual point group；低支持类别单独标记。
- 长训使用 tmux，周期保存 checkpoint、console log 和机器可读报告。除非用户明确授权，代码
  实现任务不自动启动长时间训练或外部数据下载。
- 运行命令必须使用对应隔离环境；具体环境版本和当前模型入口属于动态信息，按需查看
  `generative_model/environment/README.md` 和动态状态。

## 7. 静态上下文的失效条件

只有以下变化才更新本文：用户改变长期业务目标；`final_dataset.csv`/canonical schema/元素
词表/显式 H 政策变化；symmetry 定义或固定容差变化；数据分层架构、严格失败原则或测试
Gate 发生长期调整。普通代码修改、报错、checkpoint、loss、运行时间和阶段进度只更新
[项目动态状态](项目动态状态.md)。
