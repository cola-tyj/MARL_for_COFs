# F0.1 坐标归档与独立点群审计

## 1. 为什么在 ETKDG 前执行

F0.1 的正式 Gate 使用 stored operations/permutations 验证严格对称，但当时 `env_uae3d`
没有 pymatgen，因此没有独立重算 actual PG。若直接进入 ETKDG，一旦失败将无法区分初始构象、
orbit 对齐、力场后端或 analyzer 的责任。本审计只补齐证据，不重开或改写 F0.1 Gate。

## 2. 确定性坐标工件

在 `env_uae3d` 按冻结 F0.1 的 8 分子、3 个 sigma、2 个 seed 重放 48 cases。导出器要求：

- protocol、正式报告和 optimizer source SHA-256 完全匹配；
- optimizer status 与正式记录一致；
- final energy、bond MAE、coordinate RMSD、minimum pair distance 和 operation error 与正式
  报告的绝对差均不超过 `1e-9`。

结果五类差值全部为 `0.0`。NPZ 保存 1,446 个原子的 float64 坐标、49 个 atom offsets、case
的 package index/PG/sigma/seed/energy。独立导出两次的 NPZ 字节完全一致，SHA-256 为
`75339909c735859a429b277171d866a12a6076fa345a88e2dbf4de0b49c3f7f0`。

## 3. env_cof 独立重算结果

使用 v2 构建时相同的 `pymatgen 2025.3.10`、SciPy 1.15.2，以及 manifest 中冻结的
`0.3 Å` symmetry tolerance：

| 指标 | 结果 |
|---|---:|
| pymatgen candidate analyzer success | 48/48 |
| target-aware analysis success | 44/48 |
| compatible / all cases | 44/48 = 0.91667 |
| exact / all cases | 30/48 = 0.625 |
| stored-operation max error | `2.89e-7 Å` |

actual PG 分布：C1 4、C2 24、C2h 8、C3 6、C3h 6。C2h/C3h 是目标群的更高对称
supergroup，因此 compatible；exact 低于 compatible 是预期语义，不是失败。

## 4. 唯一失败模式

4 个不 compatible case 全部来自 `cof_001490`：`σ=0.5/1.0 Å × 2 seeds`。它们也正是
F0.1 中仅有的 4 个碰撞 case，最小原子间距最低约 `0.18 Å`，pymatgen 给出 actual `C1`。
同一分子的 canonical/hard-target 为 C2h，`σ=0.15 Å` 的两个 F0.1 输出也正常。

stored operation residual 很小但 analyzer 为 C1 并不应被掩盖：极端原子重叠使离散 permutation
等式仍可成立，却不构成可接受的分子几何。这说明 operation error 是必要条件，但必须与
collision 和 independent actual-PG 同时验收。

## 5. 正式结论与下一步

- F0.1 原正式状态仍为 `PASS_ORBIT_FORCE_FIELD_F01_ADVANCE_TO_INITIAL_CONFORMER_INTERFACE`；
  本审计是新增的非 Gate 证据，不事后篡改旧结论。
- 独立审计状态为 `FAIL_F01_INDEPENDENT_POINT_GROUP_AUDIT`，因此 initial-conformer/ETKDG
  暂缓一小步。
- 下一步只允许一个有界 collision repair：对 4 个固定失败 case 增加预注册的短程非键排斥，
  保持同一 orbit 参数化、UFF、500-step 上限和全部原 Gate，要求 4/4 collision-free、
  analyzer success 且 compatible。通过后才开始 ETKDG。
